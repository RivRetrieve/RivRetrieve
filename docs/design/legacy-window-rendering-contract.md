# Legacy window-rendering contract

This note freezes the request-window behavior of the nine portable legacy providers. It is falsification evidence, not a proposal for engine types or proof that a future design is correct. Request decomposition and rendering are distinct from local result filtering throughout: a post-hoc filter does not create another source request granularity.

> Survey and freeze the granularity set. Read the nine legacy providers' request construction and write the expected rendering for each as a table. This is the cheapest possible falsification of the entire vision — if a tenth granularity exists, it is found before any code depends on the list of nine. Delivers criterion 1's expectations as data.

> The design fits all nine. For each portable legacy provider, its window rendered through the new engine matches what its old code produced. `lt_lhmt` over `2019-12-20` -> `2020-01-10` yields `2019-12`, `2020-01`. `ch_foen` yields its exact Flux `range(start: ...Z, stop: ...Z)` string. Any provider requiring arithmetic to get there falsifies the design now rather than in a later port.

## Findings

The observed request-boundary set is: `none`; capped inclusive dates; capped Flux date span; `year`; `year-month`; product-dependent `year` / `year-month`; and product-dependent N-year chunk. Rendering vocabulary is not part of that set: in particular, `YYYYMMDD` is how `jp_mlit` renders full year or full month bounds, not a day-level request granularity. Likewise, the local result filters above do not enlarge or rename the set.

The two `none` providers retain different source behavior: `ba_fhmzbih` probes a parameterless source-fixed rolling workbook, while `pl_imgw` ensures a whole archive/cache and first consumes the requested window in the local Parquet query.

## Flux stop confirmation

Committed offline evidence was searched at the frozen ref for `Flux`, `range`, and `exclusive stop`, then `query.split_time_windows` and `query.build_flux_query` were inspected directly. The project statements found by that search are not authoritative Flux documentation.

> **UNCONFIRMED:** Authoritative Flux documentation was unreachable in the network-denied execution environment. The frozen implementation nevertheless treats `stop` as exclusive: `query.split_time_windows` sets `query_stop` to `window_end + 1 day`, and `query.build_flux_query` renders that value as Flux `range(..., stop: ...)`.

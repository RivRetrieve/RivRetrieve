# Linear annotation selection and removal of redundant retrieval work

When a caller uses `rr.pick()` on a result, narrowing its observation annotations should take work proportional to the number of annotation rows examined and retained. Live retrieval and local reads should also avoid constructing intermediate values that have no consumer. Implementing and verifying this vision completes [discussion #952](https://github.com/RivRetrieve/RivRetrieve/issues/952), one effort in [Program #938](https://github.com/RivRetrieve/RivRetrieve/issues/938).

## Where to remove work

- **Selection.** In `ObservationAnnotationTable.narrow()`, the engine already records the annotation positions to keep. It then reconstructs a set of those positions for each input row. Use the selection already made. Preserve annotation order, remap measured annotations to their selected observations, and retain unmeasured source slots according to the selected series and physical facts.
- **Filtering.** In `filter_native_with_annotations()`, create Python row dictionaries only for rows whose unmeasured-slot predicate needs one. A table containing only measured annotations should require zero dictionaries for that predicate. A measured row with a null value still counts as measured.
- **Duplicate observations.** Remove the redundant in-memory `native_links` carried through annotation transformations. At the reviewed revision, the Parquet writer derives the stored occurrence number from partition rows and measurement indices. The reader uses that number to recover the particular observation when timestamps repeat. Preserve that round trip and compatibility with existing stores. [Consumer investigation](https://github.com/RivRetrieve/RivRetrieve/issues/952#issuecomment-7100697564)
- **Accumulation.** Build accepted observation keys only for outcomes that consume them. Interval coverage can bypass that scan. Observation-level coverage still needs the retained keys and the corresponding durable outcome identity.
- **Single-result assembly.** A public fetch for one station can produce one result containing several series. Reuse already assembled data and annotations wherever equivalence is established. The public merge normalizes the request, deduplicates provenance issues, orders observations and separately orders annotations. Even rows at the same timestamp can move relative to one another. Preserve each flag's attachment to its original observation through any required reordering.

[Effort #953](https://github.com/RivRetrieve/RivRetrieve/issues/953) owns the cost of necessary passes, including checking measurement indices, sorting unordered input and processing columns during conversion. Coordinate changes in shared annotation and assembly code along that boundary. This vision works within the existing provider protocols and public result and store contracts. [Agreed division of work](https://github.com/RivRetrieve/RivRetrieve/issues/952#issuecomment-7100998687)

## Evidence of completion

Exercise public selection with growing annotated inputs while keeping a comparable fraction of rows. Show linear growth in annotation narrowing work. Use comparable before-and-after CPU time, elapsed time, work counts and peak memory for affected retrieval and local-store paths. Count the operations being removed, such as predicate dictionaries created for fully measured tables and keys enumerated solely for interval coverage. The [original measurements](https://github.com/RivRetrieve/RivRetrieve/issues/938#issuecomment-7094994897) provide workload context. No numerical speedup is required.

Compare complete results, including row and annotation order, series and physical facts, unmeasured slots, outcomes, issues, provenance and requested receipts. Include duplicate timestamps with distinguishable annotations and a single station with several series. Preserve fatal contract checks, including invalid definitions with zero observations, and independent source failure reporting. Use the [existing test contracts](../../docs/maintenance/testing.md) and the [maintained evidence workflow](../../docs/maintenance/evidence.md) for applicable retained-source checks. Report unavailable mandatory evidence as blocked.

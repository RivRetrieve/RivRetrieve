# Reuse source interpretation between acquisition and parsing

USGS and Hub’Eau interpret each observation page during acquisition to decide whether to continue and what the completed request can establish. The driver then asks the provider to parse the page again. Give the engine a shared way to use an interpretation already made for the same response in the same context. A provider author should describe each publisher’s rules once and rely on the core for work common to multiple ports. Implementing and verifying this vision completes [discussion #949](https://github.com/RivRetrieve/RivRetrieve/issues/949). Base implementation PRs on `program/938-efficient-shared-retrieval` and target that branch. [Confirmed design direction](https://github.com/RivRetrieve/RivRetrieve/issues/949#issuecomment-7109034927) · [Program branch decision](https://github.com/RivRetrieve/RivRetrieve/issues/938#issuecomment-7101159123)

## When the engine can reuse an interpretation

The driver can change the selected station and product, series scope, or known series between acquisition and parsing. Supplying catalogue series where acquisition had an empty tuple can change identity metadata or even turn an unsupported response into a successful result. Tie reuse to the particular response and the effective inputs that determine its interpretation, including the source coordinates, acquisition window and time axis. When those inputs change, produce the interpretation the new context requires. Identical bytes, URLs or acquisition IDs alone establish too little. Preserve the original call, attempts, retrieval time and dependency links when consuming the result. [Context counterexamples and candidate handoff](https://github.com/RivRetrieve/RivRetrieve/issues/938#issuecomment-7094994897)

The implementing agent owns the handoff representation and the decision about who drives follow-up requests. Explore an engine-driven loop where the provider interprets the response and identifies the next request, alongside a provider-driven loop with shared engine support. Judge the choice by what a port author must implement and how clearly the publisher’s rules can be expressed. Coordinate the boundary with [shared-product decoding #950](https://github.com/RivRetrieve/RivRetrieve/issues/950), which owns interpreting one decoded response for multiple selected products with independent outcomes.

## Prove the boundary with real provider behavior

- **USGS.** Use the page interpretation for observations, series discovery, cursor checks and cross-page duplicate detection. A USGS next link must preserve the requested collection and filters. An identifiable series and time can expose a repeat even when the measurement itself fails to parse. Remove repeated construction of the same series and physical facts across observations, while assigning each row the facts the source published for it. Exercise a change of facts within one series and an independently valid sibling alongside a malformed series.
- **Hub’Eau.** Use the page interpretation for the measurements and for deciding whether there is a valid next link. A successful first page followed by a failed request or a cursor cycle leaves the chain incomplete. Preserve the reason, affected series and exact calls. During refresh, retain previously held successful data and its original retrieval time.
- **Prerequisite responses.** A lookup can supply both the IDs needed for subsequent requests and metadata for the result. Carry both uses forward. If an observation request fails later, preserve the lookup’s successful evidence and the dependent failure. Argentina’s INA series lookup illustrates this case. The implementing agent may choose another representative prerequisite.

## Evidence and adoption

Compare equivalent paginated runs on the current Program baseline and the implementation. Count page decodes, full parses and USGS series and physical-fact construction. Report CPU time, elapsed time and peak memory, including the cost of retaining parsed tables alongside response bodies with and without requested receipts. Use the Program’s research as a workload reference. [Measurements and scope](https://github.com/RivRetrieve/RivRetrieve/issues/938#issuecomment-7100576546)

Compare observations, ordering, annotations and duplicate occurrence links, inventories, outcomes, issues, provenance and requested receipt bytes exactly. Cover changed interpretation context, native/UTC boundaries and late-page failures. Distinguish absent rows, null values, empty results and failed requests. Preserve independent series and fact outcomes and fatal validation of invalid stage output, including definitions with zero rows. Run the source-independent suite and applicable retained-source checks. Report unavailable mandatory evidence as blocked.

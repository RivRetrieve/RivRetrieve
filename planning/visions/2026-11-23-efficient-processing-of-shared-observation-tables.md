# Efficient processing of shared observation tables

A gauge can publish thousands of observations under the same physical facts, then change units partway through the record. Live retrieval, accumulated-store reads and compiled-store reads should prepare the conversion and clipping rules once for each distinct set of facts in a requested window. All three paths should process observation columns directly wherever they currently rebuild Python rows to apply those rules. Implementing and verifying this vision completes [discussion #953](https://github.com/RivRetrieve/RivRetrieve/issues/953).

Base the work on `program/938-efficient-shared-retrieval` and target implementation PRs there. The branch already includes #952, which eliminated unused work in selection and assembly. This effort owns the passes that are still necessary, including measurement-index checks, sorting unordered results and recovering annotation links from stores. It can proceed with the existing provider parsing contracts. [Agreed scope](https://github.com/RivRetrieve/RivRetrieve/issues/953#issuecomment-7103915821) · [Program branch decision](https://github.com/RivRetrieve/RivRetrieve/issues/938#issuecomment-7101159123)

## Follow each observation through the table

- **Prepare by physical facts.** For a given requested window, reuse each distinct set of facts’ admission decision, conversion factor, target unit and physical window. Respect membership of those facts in the observation’s source series. A change of unit within a series must select the corresponding factor for every affected row. Preserve measured rows with null values.
- **Select once per input table.** Use the clipping selection for both observations and their measured annotations. If two observations share a timestamp and only the second carries a flag, the flag must still identify the second occurrence after clipping, sorting and decoding an existing store partition. Apply the same physical window rule to each unmeasured annotation using its own facts and timestamp.
- **Check stage boundaries.** Validate supplied series and fact definitions even when there are zero observations. Independently check the actual converted table against the admitted facts and requested bounds. Preserve fatal failures for invalid stage output, including unknown or conflicting facts, mismatched coordinates or units, invalid timestamp anchors and invalid measurement links. Preserve the distinction between native calendar labels and UTC acquisition bounds. Public UTC conversion continues to use the published zone, including its existing handling of unknown zones and ambiguous local times.
- **Reduce table passes and allocation.** Apply the shared rules during native validation, clipping, conversion, annotation handling, UTC conversion, result assembly and store decoding. Preserve public ordering and the stored occurrence ordinals that identify duplicate observations. Choose Polars operations and internal representations that fit each path. Once all consumers of a response have finished with its body, retain only the evidence required for provenance and any requested receipt. Preserve exact receipt bytes, acquisition identity, prerequisite calls and original retrieval times.

## Bypass and acquisition outcomes

With `cache="bypass"`, skip copies made solely to persist a store update. Today the driver also uses selected rows to classify successful and empty outcomes, recover exact observation keys, and compose contributions from multiple acquisitions. Keep enough evidence for those decisions. Use the same outcome and overlap rules across cache modes, including rejection of overlapping independent snapshot keys. Check acquisition-axis consistency for contributions to the same fact in the same series. Independent facts within one series can use different axes, even when they arrive in one payload. Defer a broader redesign of acquisition composition if it proves necessary.
